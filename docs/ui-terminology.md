## 처리 흐름 용어 (T25)

| 용어 | 뜻 |
|---|---|
| 담당자 | 그 인시던트를 맡은 분석가(활성 분석가·관리자이고 그 캡처를 볼 수 있는 사람). 상태와 따로 둔다. 비활성이 되었거나 허용 캡처가 바뀐 사람도 자동으로 풀지 않고 "비활성" 표지를 붙여 보인다 |
| 미배정 | 담당자가 없음(지정한 적이 없거나 해제됨) |
| 내 담당 | 로그인한 사용자가 담당자인 인시던트(조회자는 담당자가 될 수 없어 선택지가 없다) |
| 경과 | 탐지 시각에서 기준 시각까지 지난 시간(미종결). 고정 스냅샷이면 그 기준 시각까지 |
| 착수 | 처음 "조사 중"으로 바뀐 것(상태 이력의 첫 `investigating`). **담당 지정은 착수로 치지 않는다.** 조사를 시작할 때 미배정이면 시작한 사람이 담당자로 자동 지정되므로 보통 같은 시각이지만, 담당만 정하고 상태를 바꾸지 않은 건은 계속 착수 지연이다 |
| 착수 목표 | 실습망 신규 인시던트를 탐지 뒤 이 시간 안에 조사 시작해야 한다: High 30분 · Medium 4시간 · Low 24시간(기본값, 설정 `dashboard.sla.ack.*`). 가져온 데이터는 재생 데이터라 따지지 않는다. **우선순위는 지금 값이다**: 검토 결정 뒤 High에서 Medium으로 내려가면 목표도 4시간으로 바뀐다 |
| 착수 지연 | 착수 목표 시각(탐지 시각 + 목표)이 기준 시각보다 앞인데 아직 신규인 실습망 인시던트(같으면 지연 아님) |

| 착수 시간(MTTA) | 착수 시각 − 탐지 시각. 기간은 착수 시각 기준. 조사 중 기록 없이 종결된 건(파이프라인 반영·옛 자료)은 제외에 센다. 다시 연 건(T53)의 착수 시각은 첫 착수 그대로다. 다만 조사 중 기록 없이 종결된 건을 다시 열면 다시 연 시각이 착수 시각이 된다(다시 열기도 `investigating` 이력이다). 그래서 착수 시간에 큰 값이 들어갈 수 있다 |
| 처리 시간(MTTR) | 종결 시각 − 탐지 시각. 종결 시각은 지금 상태가 종결일 때의 상태 갱신 시각이다. 다시 열었다가 다시 종결한 건(T53)은 마지막 종결 시각 기준이고, 처음 종결까지의 시간은 이력에만 남는다. 다시 연 동안(분석 중)은 처리 시간에 들지 않는다. 기간은 종결 시각 기준. 판정별(정탐·오탐·정상·판정 없음)로도 본다. 목록의 "처리 N"과 같은 값 |
| 중앙값 · p90 | 가장 가까운 순위 백분위(정렬 뒤 `ceil(p·n)`번째, PostgreSQL `percentile_disc`와 같다). MTTx는 보통 평균(Mean)이지만 며칠 묵은 몇 건이 평균을 크게 끌어올리므로 중앙값과 p90을 보인다 |
| 표본 부족 | 건수가 10건 미만(값은 보인다). 0건이면 "-" |
| 제외 | 값이 음수이거나 계산에 필요한 시각이 없는 건 |

## 자동 분류 기준 (T18, zeek_AD와 공유)

인시던트 화면의 "우선순위"는 서버가 계산한다(T23: `GET /api/incidents/queue`의 `priority`, SQL `ZeekadReadMapper.xml` `unifiedQueueBase`. 화면·상세 헤더는 서버 값을 그대로 보인다. 옛 `computePriority`는 지웠다). 자동 판단이며 분석가 판정이 아니다. 근거: 2026-11-21 결정 "자동 분류 우선순위 규칙 수정"(`docs/design-decisions.md`). 그 결정의 높음/중간/낮음은 화면 표기 High/Medium/Low와 같은 등급이다(T18b, "화면 용어를 관제 표준 용어로 재정비").

| 우선순위 | 조건(위에서부터 먼저 맞는 것) | 쓰는 필드(zeek_AD 값) |
|---|---|---|
| 없음(`-`, 회색) | 인시던트 상태가 종결 | `zeekadStatus == closed`(소문자로 비교. `null`·빈 문자열은 신규로 보고, 등록되지 않은 값은 종결이 아닌 것으로 본다) |
| High(빨강) | 발송 판단 "발송" 또는 에스컬레이션 대기(T21: 이름만 "발송 판단"으로 맞춤, 계산 그대로) | `zeekadWouldSend`(zeek_AD `would_send`), `zeekadReviewPending`(검토 결정 전 에스컬레이션) |
| Medium(밝은 회색) | 교차 탐지(2개 이상 모델) 또는 AI 분석 리포트 있음 | `zeekadAlsoFlaggedBy` 1개 이상(zeek_AD `zeekad_also_flagged_by`. `multiModelFlagged`는 쓰지 않는다), `hasReport` |
| Low(흐린 회색) | 그 밖 | — |

**중요 자산(T52).** 위 표의 값은 기본 우선순위(API `priorityBase`)다. 관리자가 등록한 중요 자산(앱 DB `critical_assets`, IPv4 주소 하나)이 호스트(`host_ip` 원문)인 미종결 인시던트는 한 단계 올린다(Low → Medium, Medium → High. High와 종결은 그대로). 올린 값이 `priority`이고 필터·정렬·착수 목표·요약·호스트 위험도·현황판이 모두 이 값을 쓴다. 중요 자산 여부는 `assetCritical`(종결 건에도 붙는다), 이름은 `criticalAssetName`(분석가·관리자만. 조회자는 늘 `null`)이다. 자산의 설명은 관리자 화면에만 있다. 표지는 우선순위 배지 옆의 왕관 표지다. 인시던트 목록의 데스크톱 표에서는 우선순위 배지 오른쪽 위 모서리에 작은 원 안의 왕관 아이콘만 보이고(T62, 글 표지가 1280px 표를 넘치게 했다) 우선순위 열 머리 툴팁이 왕관의 뜻을 알린다. 휴대폰 카드·상세 머리줄·같은 호스트 인시던트·호스트 위험도는 "중요 자산" 글 표지다. 어느 쪽이든 툴팁과 화면 읽기 글은 같다.

- 정렬(T23 서버): 기본은 우선순위 오름(High 먼저) → 같으면 중요 자산 먼저(T52. 내림이면 나중, 종결 무리 안에도 같은 키) → 탐지 시각 최근 → 캡처 ID → 캡처 안 순위. 종결(우선순위 없음)과 세션 수·시각이 없는 인시던트는 방향과 상관없이 맨 뒤. 상태 순서는 신규 → 분석 중 → 등록 안 된 값 → 종결.
- 요약 띠의 수는 서버 `summary`다. 띠 자체의 축(우선순위·에스컬레이션 대기·경보 발송)을 뺀 나머지 거르기(기간·수집원·필터)를 적용한 집합에서 세므로 띠를 눌러 걸러도 띠의 수는 바뀌지 않는다.
- URL 쿼리(T23): `period=1h|24h|7d|30d|all`(기본 24h, URL에 남기지 않음), `source=live|imported`, `captureId`, `priority=high|medium|low`, `reviewPending=true`, `alerted=true`, `pickedBy`, `role`, `status`, `hasReport`, `wouldSend`, `asset`, `sort=priority|detected|start|connections|status`, `dir=asc|desc`, `page`(1부터), `size=25|50|100`. 모두 서버로 보낸다. 옛 `jobId`는 지우고 안내하며, 옛 `sort=rank`는 기본 정렬로 바꾼다.
- 심각도 같은 원천 우선순위 데이터, 담당자·탐지 후 경과·처리 시간은 `T25`에서 다룬다. 정렬·쪽 나눔은 T23부터 서버가 한다.

### Slack 알림 표시 (T38)

- 알림 본문은 `payloadJson`의 `text`, 전문은 `blocks`다. `header`는 제목, `section`의 글은 문단, `fields`는 이름과 값, `context`는 작은 글, `actions`는 버튼 이름만 보인다. 모르는 블록, 그림 요소, `accessory`는 건너뛴다.
- 글 풀이 순서: (1) `<http…|글>`·`<mailto:…|글>`은 글만 남기고 `<http…>`·`<#…>`·`<@…>`·`<!…>`는 지운다. (2) 맨 URL을 지우고 `사건:`처럼 이름만 남은 줄은 그리지 않는다. (3) 낱말 경계의 `*굵게*`·`_기울임_`만 푼다(`transformer_v2` 같은 낱말 안 밑줄과 시간 범위 `~`는 그대로). (4) `&gt;`·`&lt;`·`&amp;`를 글자로 푼다. `[근거 보기](…)` 같은 대괄호 글은 글자 그대로다.
- 조회자 응답은 서버가 `payloadJson` 글 잎의 IPv4를 이미 가린다. 화면은 받은 글을 그대로 그리고 본문 속 가명(`H`·`X1`)에 주소를 붙이지 않는다.
- **스레드 기록 없음**: `created_at`이 2026-11-19 06:20 UTC(`2026-11-19T06:20:00Z`)보다 이른 알림은 zeek_AD가 스레드 정보(`zeekad_thread_parent`·`zeekad_reply_broadcast`)를 기록하기 전 기록이다. 그런 알림 가운데 묶음의 둘째부터는 첫 알림의 스레드 답글이었는지 알 수 없어 이 표지를 붙인다. 답글로 그리지도 채널 알림이라고 적지도 않는다. 공개 스냅샷의 알림은 모두 이 기준 전 기록이다. 지금 zeek_AD는 같은 사건의 뒤 알림을 첫 알림의 스레드 답글로 보낸다(zeek_AD 데이터 계약 v2, 2026-11-23 회신).

### 조사 동선과 내보내기 (T44)

모두 이미 받은 응답으로만 만든다. 서버에 더 묻지 않으므로 조회자는 화면에 보이는 가려진 값만 복사하고 내려받는다.

- **대역 표지**: 앞 두 옥텟 `A.B`만 본다. 조회자에게 가려진 주소(`A.B.*.*`)도 같은 규칙이다. `10/8`·`172.16/12`·`192.168/16`은 "사설"이다. `0/8`, `127/8`, `169.254/16`, `100.64/10`, `198.18/15`, `224` 이상은 표지를 달지 않는다. 나머지 IPv4는 "외부"다. IPv6, 포트가 붙은 글, 가명에는 표지가 없다. 주소를 조회하거나 밖으로 보내지 않는다.
- **주요 통신 구조**: 증적이 있고 상대 IP가 하나 이상일 때만 그린다. 화살표는 인시던트의 통신 방향(`zeekadRole`)이다. 출발지면 대상 호스트에서 상대 IP로, 목적지면 반대로 향하고 그 밖의 값이면 화살표 없는 선이다. 세션마다의 방향이 아니다. 선 굵기는 가장 많은 상대 대비 세션 수 비율로 1.5~5.5이고 세션 수가 모두 0이면 2다. 숫자가 아니거나 음수인 세션 수는 0으로 본다. 화면 판독기에는 그림을 감추고 같은 내용의 표(대상 호스트·방향·상대 IP·세션 수)를 준다.
- **p95 대비 배수**: `baseline.<지표>` 값이 사전에 있는 지표이고 비율 지표(`_ratio`)가 아니며 평소 p95가 0보다 크고 이번 인시던트 최대가 평소 p95를 넘을 때만 보인다. 배수는 값 글의 "(평소 p95의 N배)"와 같은 수다. 한 자리로는 1배로 보이는 값만 둘째 자리까지 쓴다(`1.04배`). 막대 눈금의 끝은 이번 인시던트 최대, 평소 p95, 평소 최대 가운데 큰 값이다. 화면은 값을 다시 판정하지 않는다.
- **요약 복사**: 제목 `# 인시던트 #번호 요약`(번호가 없으면 `# 인시던트 요약`), 기본 정보(우선순위·상태·판정·호스트·방향·수집원·탐지 시각·발생 구간·탐지 모델), 주요 증적(세션 수·송신 바이트·수신 바이트·주요 상대 IP 최대 5개·주요 포트 최대 3개), 리포트가 있으면 구분·검증 결과와 관측 요약·확인된 사실·관련 ATT&CK 기법 후보·추가 확인 권고다. 템플릿 리포트면 `[템플릿 리포트 — AI 리포트 대체]` 줄을 넣는다. 시각은 KST라고 적는다. 인시던트 ID, 모델 버전, `zeekad_*`·`dashboard.*`·`evidence.v1` 같은 내부 이름은 넣지 않고 리포트 글에 인용돼 있으면 "(식별자 생략)"으로 바꾼다. 주소·호스트 이름·포트는 코드 표기로 감싸고 서술 글의 마크다운 기호와 꺾쇠는 이스케이프한다. 값 안의 줄바꿈은 한 줄로 편다. 호스트 이름은 관측 대상이 정하는 글이어서 붙여 넣은 곳에서 제목이나 링크로 읽히지 않게 한다.
- **CSV 내보내기**: 열은 번호, 우선순위, 탐지 시각(KST), 호스트 IP, 호스트 이름, 수집원, 통신 방향, 발생 시작(KST), 발생 종료(KST), 탐지 모델, 교차 탐지, 리포트 종류, 발송 판단, 경보 발송, 상태, 판정, 담당, 세션 수다. 값은 화면과 같은 표시 이름과 시각(KST)이고 값이 없는 칸은 `-`가 아니라 빈 칸이다. 지금 쪽의 행만 담는다. UTF-8 BOM으로 시작하고 줄은 CRLF로 나눈다. 모든 칸을 쌍따옴표로 감싼다. 앞의 스페이스를 건너뛴 첫 글자가 `=`, `+`, `-`, `@`, 탭, 줄바꿈이면 칸 맨 앞에 작은따옴표를 붙여 표 계산 도구가 수식으로 실행하지 않게 한다.

### 호스트·ATT&CK 조건과 묶음 표지 (T45)

- **호스트 조건(`hostIp`)**: 온전한 IPv4(`A.B.C.D`)와 가려진 IPv4(`A.B.*.*`)만 받는다. 옥텟은 0~255이고 `01`처럼 앞에 0을 붙인 꼴, IPv6, 포트가 붙은 글, `A.B.C.*`는 받지 않는다(서버 `400`). 분석가·관리자에게 온전한 주소는 그 주소와 정확히 같은 호스트다. 가려진 주소는 누구에게나 그 대역의 호스트 전부다. 조회자가 온전한 주소를 넣으면 그 호스트가 있든 없든 0건이다. 조회자는 가려진 값으로만 맞춰 보므로 원문 주소가 있는지 알 수 없다. 자산 검색(`asset`, 부분 일치)과 함께 쓰면 둘 다 걸린다.
- **ATT&CK 조건(`attack`)**: 기법 ID 꼴(`T` + 숫자 4자리, 하위 기법은 `.` + 숫자 3자리, 대소문자 무시)이면 기법이고 그 밖은 전술이다. 기법은 하위 기법까지 정확히 같아야 한다(`T1059`는 `T1059.001`을 포함하지 않는다). 전술은 소문자로 바꾸고 공백·밑줄을 하이픈으로 바꿔 비교하므로 `Credential Access`, `credential_access`, `credential-access`가 같다. 대상은 인시던트의 최신 리포트에 적힌 관련 ATT&CK 기법 후보다. 후보는 확정이 아닌 가설이고 리포트가 없는 인시던트는 어떤 값에도 맞지 않는다.
- **묶음 N건**: 인시던트가 속한 Slack 알림 묶음의 인시던트 수다. 묶음의 뜻과 건수는 상세 Slack 탭과 같다(최초 알림 인시던트와 그 스레드에 붙은 인시던트 가운데 볼 수 있는 수집원의 최신 목록에 있는 것). 지금 고른 기간·수집원과 상관없이 세므로 누르면 가는 전체 기간 목록의 건수와 같다. 여러 묶음에 속하면 건수가 가장 큰 묶음을 보인다. 최초 알림 인시던트를 볼 수 없거나(허용 밖 수집원, 번호 없음) 1건뿐이면 표지가 없다. 최초 알림 인시던트 자신의 알림 기록이 없으면 그 행에는 표지가 없고 붙은 인시던트의 행에만 있다.

### 현황판 위협 가시성 (T45b)

세 패널 모두 현황판의 지금 조건(기간·수집원·고른 캡처)에 맞는 인시던트만 센다. 같은 `overview` 응답으로 그리므로 불러오기 실패와 "최신 값이 아닙니다" 표시는 현황판의 다른 패널과 같이 움직인다. 각 줄의 건수는 그 줄을 눌러서 가는 인시던트 목록의 건수와 같다. 알림 묶음 줄은 "전체" 건수가 그렇다("기간 내" 건수는 지금 조건 안의 수라 묶음 전체 목록의 건수와 다를 수 있다). 머리의 "후보가 있는 인시던트 N건"에는 링크가 없다.

- **ATT&CK 전술·기법 후보**: 인시던트의 최신 리포트에 적힌 관련 ATT&CK 기법 후보를 센다. 값의 정규화는 인시던트 목록의 `attack` 조건과 같다(위 절). 한 인시던트의 후보에 같은 전술이나 기법이 여러 번 나와도 한 번이다. 한 인시던트가 여러 전술·기법에 들어가므로 합은 인시던트 수와 다르다. 기법 ID 꼴이 아닌 ID와 전술 이름으로 읽을 수 없는 값은 세지 않는다. 기법 이름은 그 ID에 가장 많이 붙은 후보 이름이다. 전술은 전부, 기법은 건수가 많은 순서로 10개를 보이고 고유 기법 수가 더 많으면 "외 N개"를 적는다. "후보가 있는 인시던트 N건"은 이렇게 센 전술이나 기법이 하나라도 있는 인시던트 수다.
- **위험 호스트 상위 5**: 통신 방향이 출발지인 인시던트와 목적지인 인시던트를 따로 호스트 주소별로 묶는다. 순서는 미종결 High 건수, Medium 건수, Low 건수, 전체 건수(종결 포함), 마지막 탐지 시각(늦은 쪽), 주소 순이다. 종결은 우선순위가 없어 전체 건수에만 든다. 여러 수집원에 걸친 같은 주소는 한 줄이다. 조회자는 가려진 주소(`A.B.*.*`) 단위로 묶은 줄을 본다. 그 줄은 호스트 하나가 아니라 대역이고, 누르면 그 대역의 인시던트 목록이 열린다.
- **주요 알림 묶음**: 묶음의 뜻과 "전체" 건수는 인시던트 목록의 "묶음 N건" 표지, 상세 Slack 탭과 같다. 지금 조건의 인시던트가 한 건 이상 들었고 전체가 2건 이상이며 최초 알림 인시던트를 볼 수 있는 묶음만 나온다. "기간 내"는 지금 기간·수집원·캡처 조건 안의 인시던트 수다. 순서는 기간 내 건수, 전체 건수, 기간 내 가장 늦은 탐지 시각, 최초 알림 인시던트 번호(큰 쪽) 순이고 위에서 5줄이다. 최초 알림 인시던트가 지금 인시던트 목록에 없으면 호스트 자리에 `-`를 둔다. 묶음이 아주 많은 조건에서는 서버가 묶음 계산을 생략하고 그렇게 알린다(빈 값과 구별한다).

### 호스트 위험도와 같은 호스트 인시던트 (T46)

- **묶는 단위**: 분석가·관리자는 호스트 주소 하나가 한 줄이다. 여러 수집원에 같은 주소가 있으면 한 줄로 합친다. 조회자는 가려진 주소(`A.B.*.*`)가 한 줄이고 그 대역의 호스트 전부를 합친 값이다. 서버가 처음부터 가려진 주소로 묶으므로 줄 수와 순서로 원문 호스트 수를 알 수 없다.
- **줄의 값**: 지금 조건(기간·수집원)의 인시던트만 센다. 미종결 우선순위 건수는 인시던트 목록과 같은 자동 분류 값이고 종결된 인시던트는 우선순위가 없어 인시던트 수에만 든다. 세션 수는 인시던트 세션 수의 합이다. 탐지 모델은 건수가 많은 순이다. 호스트 이름과 관측 계정은 글자 순으로 5개까지 받고 전체 수를 따로 받는다. 줄의 인시던트 수는 줄을 눌러 가는 인시던트 목록(같은 기간·수집원, 조건 `hostIp`)의 건수와 같다.
- **위험도 순서**: 기본 순서는 High 건수, Medium 건수, Low 건수, 인시던트 수, 마지막 탐지 순으로 큰 것이 먼저이고 끝까지 같으면 주소 오름차순이다. 새로 만든 점수가 아니다. 다른 열로 정렬하면 그 값이 같은 줄끼리 이 순서를 따른다. 마지막 탐지가 없는 줄은 방향과 상관없이 맨 뒤다.
- **목적지 → 출발지 전환**: 한 호스트가 같은 캡처 안에서 목적지로 탐지된 인시던트의 가장 이른 발생 시각보다 뒤에 출발지로 탐지된 인시던트가 있으면 표지를 붙인다. 발생 시각이 같으면 붙이지 않는다. 오탐·정상으로 종결된 인시던트는 빼고 본다(정탐 종결은 뺀 것이 아니다). 캡처가 다르면 견주지 않는다. 지금 조건 안의 인시던트만 보므로 기간을 좁히면 표지가 사라질 수 있다. 침해가 확정됐다는 뜻이 아니라 먼저 볼 호스트를 고르는 표시다. 조회자에게는 계산하지 않는다(가려진 대역 안의 서로 다른 호스트를 한 호스트의 전환으로 읽으면 안 된다). 조회자가 "전환만" 주소(`roleTransitionOnly=true`)를 열면 화면이 그 조건을 빼고 부른다.
- **검색**: 주소·호스트 이름·관측 계정 가운데 하나라도 검색어를 품으면 맞다(대소문자 무시, 100자까지). 줄에 보이지 않는 6번째부터의 이름·계정에도 맞는다. 조회자는 가려진 글에만 맞으므로 원문 주소나 계정 이름으로 찾으면 0건이다.
- **줄 링크**: 지금 기간·수집원을 유지한 인시던트 목록에 `hostIp`를 붙인다. 화면 기본 기간(7일)일 때도 주소에 기간을 적는다(인시던트 목록의 기본 기간은 24시간이다). 이 화면의 검색·전환 거르기는 잇지 않는다. 주소가 온전한 IPv4나 `A.B.*.*`가 아니면(IPv6 등) 링크 없이 글로 둔다.
- **읽는 범위**: 조건 안의 인시던트가 5,000건을 넘으면 목록 대신 "기간이나 수집원을 좁혀 주세요" 오류다(인시던트 목록 자산 검색과 같은 한도). 자동 갱신은 없다.
- **같은 호스트의 다른 인시던트**: 볼 수 있는 수집원 전체의 최신 목록에서 같은 호스트(조회자는 같은 대역)의 인시던트를 찾고 지금 보는 인시던트는 뺀다. 기간 조건은 없다. 발생 시각이 이 인시던트와 가까운 순으로 10건을 고르고(같으면 탐지 시각이 늦은 것 먼저) 발생 시각이 늦은 것부터 보인다. 간격 글은 이 인시던트의 발생 시각과 견준 값이다(1분 미만 "같은 시각", 그 밖은 분·시간·일 단위에 "전"·"뒤"). "전체 보기"는 그 호스트의 전체 기간 인시던트 목록이고 지금 보는 인시던트도 들어 있다. 인시던트 ID 원문은 응답에 없다.
- **관측 계정 가리기**: 조회자에게는 관측 계정 이름을 첫 글자 + `***`로 가린다. 값이 여러 개(목록)면 하나씩 가리고 글이 아닌 값도 글로 바꿔 가린다. 호스트 위험도 화면에서는 가린 뒤 같은 글이 된 계정을 하나로 센다(`alice`와 `adam`은 `a***` 하나다). 호스트 이름은 계정 이름과 같은 글일 수 있지만(컴퓨터 계정) 개인정보가 아니어서 IPv4만 가린다.

### 신뢰하지 않는 글자열의 표시 (T64)

호스트·사용자 이름은 접속하는 쪽이 정하고 AI 리포트 글은 LLM이 쓴다. 서버(`T63`)가 응답 직전에 이런 글을 한 번 처리하고 화면은 받은 글을 다시 바꾸지 않고 글자 그대로 보인다. 모든 글은 React 글자 노드로 그리므로 HTML·마크다운·Slack 표기는 해석되지 않는다.

- **숨은 문자 표지**: 분석가·관리자 화면에서는 제어 문자, 서식 문자(방향 전환 U+202E 등), 줄·문단 구분자, 보이지 않는 문자(한글 채움 문자, 변형 선택자 등), 짝 없는 서러게이트, 한 글자에 3개를 넘게 붙은 결합 문자가 그 자리에 `[U+202E]` 꼴(16진 대문자 4~6자리)로 보인다. 이름에 이런 글자가 있다는 것 자체가 단서라 지우지 않는다. 이름 칸에서는 줄바꿈·탭도 표지이고 리포트 글 같은 여러 줄 칸에서는 줄바꿈·탭이 남는다. 이름에 글자 그대로 `[U+202E]`를 넣으면 진짜 표지와 구별되지 않는다(둘 다 바깥 글이다).
- **조회자의 제거 표시**: 조회자 화면에는 표지가 없다. 서버가 숨은 문자를 지우고 끝에 ` [보이지 않는 문자 N개 제거]`를 붙인다(예: `a*** [보이지 않는 문자 1개 제거]`). N은 지운 글자 수다. 주소가 들 수 있는 글은 원문에서 한 번 가리고, 숨은 문자를 지우고, 다시 가린다(옥텟 사이에 폭 없는 문자를 끼운 주소도 가려진다). 관측 계정 이름은 숨은 문자를 지운 값의 첫 글자 + `***`이고 첫 글자가 이모지처럼 BMP 밖이면 `***`다. 지금 가리지 않는 칸(표시 이름 등)은 숨은 문자만 지운다. 제거 표시는 길이 상한 밖에 붙는다.
- **길이**: 서버가 이름 256자, 값 1,000자, 글 4,000자(코드 포인트)에서 자르고 `…(N자 생략)`을 붙인다. N은 버린 글자 수다. 화면은 더 자르지 않는다.
- **이름 칸의 폭**: 이름·계정·표시 이름이 나오는 칸은 폭이 정해져 있다. 한 줄 칸(인시던트 목록의 호스트 이름·담당자, 상세 머리줄의 호스트 이름, 호스트 위험도의 호스트 이름·관측 계정, 사이드바의 사용자, 중요 자산 관리의 고친 사람)은 말줄임하고 툴팁에 전체를 둔다. 표의 칸과 문장 속 이름(관측 계정, 감사 로그의 행위자·대상 캡처·대상 인시던트, 이력의 변경자·결정자, 담당 지정자, 대응 조치 기록자, 사용자 관리의 아이디·표시 이름, 중요 자산 관리의 이름·설명)은 정한 폭에서 줄을 바꿔 전체를 보인다. 리포트 글은 띄어쓰기 없는 긴 글도 칸 안에서 줄을 바꾼다. 운영 현황의 Slack 일일 요약 미리보기는 높이를 정하고 상자 안에서 스크롤한다.
- **"AI 작성" 표지**: AI 리포트 탭 머리의 종류 표지와 같은 규칙을 요약 탭의 리포트 글 칸(관측 요약, 확인된 사실, 가능한 해석, 추가 확인 권고)마다 붙인다. LLM이 쓴 리포트면 "AI 작성", 템플릿으로 바꾼 리포트면 "템플릿 리포트" 표지다. 리포트가 없어 자동 요약을 보일 때는 "자동 요약" 표지 그대로다. 관련 ATT&CK 기법 후보는 LLM 글이 아니라 검색으로 찾은 MITRE 자료여서 "AI 작성"을 붙이지 않고 "확정이 아닌 가설" 표지를 둔다.
- **AI 리포트 탭 안내 줄**: LLM이 쓴 리포트(`reportKind`가 `llm`)면 머리에 "AI(LLM)가 쓴 글입니다. 근거 사실과 대조했지만 해석이 맞다는 뜻은 아닙니다. 판단은 증적으로 확인하세요."를 한 줄 보인다. 템플릿 리포트에는 이 줄 대신 템플릿 안내 줄이 있다.
- **ATT&CK 후보 접기**: 받은 순서가 파이프라인의 순위다. 앞 3개와 가능한 해석이 인용한 후보(`attack_ids`)는 늘 보이고 나머지는 "나머지 후보 N개"로 접는다. 보이는 후보는 받은 순서대로다. 서버는 개수를 자르지 않는다. 요약 복사에도 보이는 후보만 싣고 끝에 "외 N개"를 적는다.
- **내보내기**: 요약 복사와 CSV는 칸마다 숨은 문자를 같은 표지로 바꾼 뒤 이스케이프한다(분석가가 쓴 대응 조치 메모 포함). 내보낸 글은 앱 밖에서 열리기 때문이다. 줄바꿈·탭은 남기고 요약 복사는 한 줄로 편다. `\r\n`은 `\n`이 되고 홀로 있는 `\r`은 표지가 된다. 서버가 넣은 표지는 ASCII라 다시 바뀌지 않는다. 요약 복사의 서술 글은 `_`·`~`·`|`·`&`도 이스케이프한다(`&#x202E;` 같은 문자 참조를 렌더러가 글자로 풀지 않게). CSV의 수식 방어(작은따옴표)는 표지로 바꾼 값으로 판단한다.

## AI 리포트 근거 사실 이름 (T37, zeek_AD와 공유)

zeek_AD 리포트 근거 사실(`zeekad_facts`, `[{id, name, value}]`)의 이름을 화면 항목 이름으로, 값을 읽기 좋은 모양으로 바꾸는 사전이다(`frontend/src/utils/factLabels.ts`). 이름 규칙으로 바꾸고, 상태·역할·모델 이름은 위 표시 이름 사전을 다시 쓴다. 공개 데이터의 이름 102가지(2026-11-23, `demo`가 볼 수 있는 캡처)를 모두 덮는지 시험한다(`frontend/src/test/publicFactNames.ts`).

- 사전에 없는 이름, 이름이 정한 모양과 다른 값(모르는 키가 더 있는 객체 포함)은 원문을 흐린 고정폭 글자로 보인다(`data-raw`). 지어내거나 숨기지 않는다.
- 값을 다시 계산해 리포트 문장과 맞는지 판정하지 않는다. 화면은 zeek_AD가 준 값을 읽기 좋게 보일 뿐이다(평소 p95의 몇 배인지만 나눗셈으로 보인다).
- 숫자는 천 단위 구분, 소수는 둘째 자리까지 보인다. 객체 안 null 칸은 `-`다(0으로 바꾸지 않는다). 원문 이름과 원문 값은 항목 툴팁에 있다.
- 값 글 전체가 가명 키(`H`·`I1`·`X1` 등)와 같을 때만 `X1(203.0.*.*)`처럼 주소를 붙인다(문장과 같은 모양, 주소는 `report.pseudonyms`라 조회자는 가린 주소). `X1:443`처럼 섞인 글에는 붙이지 않는다.
- 리포트가 인용한 번호가 사실 목록에 없으면 "근거 정보 없음"과 번호를 보인다.

| 사실 이름(규칙) | 항목 이름 | 값 |
|---|---|---|
| `connection_count` / `unique_peers` / `unique_destination_ports` / `payload_bytes_inflated_connections` | 세션 수 / 고유 상대 IP 수 / 고유 목적지 포트 수 / 페이로드 바이트가 부푼 세션 수 | 천 단위 구분 |
| `queue_rank` | 탐지 순위 | `N위` |

| `incident_duration_seconds` | 인시던트 지속 시간 | `1시간 5분`, `45분`, `30초` |
| `host_role` | 통신 방향 | 출발지·목적지(`hostRole`) |
| `picked_by_model` / `also_flagged_by_models` | 탐지 모델 / 함께 탐지한 모델 | 모델 표시 이름(`detectionModel`), 여럿은 쉼표, 빈 배열은 "없음" |

`baseline.<지표>` 지표 이름: `connections_per_window` 구간당 세션 수, `dce_rpc_calls_per_window` 구간당 DCE-RPC 호출 수, `distinct_peer_ports_per_window` 구간당 고유 상대 포트 수, `distinct_peers_per_window` 구간당 고유 상대 IP 수, `dns_max_query_length_chars` DNS 최장 질의 길이(`N자`), `dns_nxdomain_per_window` 구간당 DNS 없는 도메인 응답, `dns_queries_per_window` 구간당 DNS 질의 수, `ftp_failures_per_window` 구간당 FTP 실패 응답, `http_errors_per_window` 구간당 HTTP 오류 응답, `http_requests_per_window` 구간당 HTTP 요청 수, `icmp_connection_ratio` ICMP 세션 비율, `kerberos_failures_per_window` 구간당 Kerberos 실패 수, `payload_bytes_received_by_host_per_window` 구간당 자산 수신 페이로드 바이트(바이트 단위), `payload_bytes_sent_by_host_per_window` 구간당 자산 송신 페이로드 바이트(바이트 단위), `rejected_connection_ratio` 거부된 세션 비율, `smb_file_actions_per_window` 구간당 SMB 파일 작업 수, `smb_mappings_per_window` 구간당 SMB 공유 폴더 연결, `tls_without_sni_per_window` 구간당 SNI 없는 TLS 세션, `unestablished_connection_ratio` 성립하지 않은 세션 비율.

- 이름이 `_ratio`로 끝나는 지표는 비율이다. 값이 0~1이면 %(소수 한 자리)로 보이고, 그 밖의 값(음수, 1 초과)은 바꾸지 않고 그대로 보인다. 공개 데이터의 세 비율 지표 값은 모두 0~1이다(설계자 확인 2026-11-23).
- 구간은 zeek_AD 탐지의 5분 윈도우다.

## 탐지 모델 표시 이름 (T18b, 출처 zeek_AD)

zeek_AD 데이터 계약 v2 "모델 표시 이름" 절(zeek_AD `docs/design-discussion-log.md` Q63)에서 확정한 표다(2026-11-21). 대시보드는 그대로 쓴다(`frontend/src/utils/labels.ts`의 `detectionModel` 사전과 `DETECTION_MODEL_INFO`). DB 값(`zeekad_picked_by`, `zeekad_also_flagged_by`, `zeekad_model`, `model_bundles.thresholds`의 키, `feedback_summary.zeekad_picked_by`)은 바뀌지 않는다.

| 식별자 | 표시 이름 | 모델 종류 | 툴팁 | zeek_AD 공유 필요 |
|---|---|---|---|---|
| `tail_rarity_v2` | 기준선 이탈 | 통계 기준선 | 5분 구간의 통신 특징 42개(연결 수, 목적지 포트 수, 연결 실패 비율, 프로토콜 로그 등) 중 정상 기간에 거의 없던 값이 있는 정도. 가장 드문 특징 하나가 점수다. 정찰·스캔, 인증 실패 반복에 강하다. | 예(zeek_AD 출처) |
| `transformer_v2` | 행위 패턴 이탈 | Transformer | 이 자산의 직전 1시간(5분 구간 12개)으로 다음 5분을 예측하고, 실제와 다른 정도. 다른 자산이 아니라 자기 평소 흐름과 비교한다. 이력이 없는 첫 구간에서는 높게 나올 수 있다. | 예(zeek_AD 출처) |
| `tgn_recon` | 통신 관계 이상 | TGN(시간 그래프 신경망) | 호스트 사이의 연결을 시간 그래프로 학습해, 예상하기 어려운 연결이 나온 정도(구간 안에서 가장 예상 밖인 연결 하나 기준). beacon처럼 양은 적어도 상대가 특이한 통신을 올린다. 이상 호스트와 통신한 정상 호스트도 함께 올라갈 수 있다. | 예(zeek_AD 출처) |

- 표시 규칙: 인시던트 목록·운영 화면 결론 집계·임계값 같은 표에는 표시 이름만 보인다(툴팁에 "모델 종류 · 식별자"와 설명). 인시던트 상세(탐지 모델, 모델별 탐지 윈도우)에는 표시 이름 옆에 "모델 종류 · 식별자"(예: "Transformer · transformer_v2", `data-raw`)를 함께 보인다. 필터의 탐지 모델 선택지는 표시 이름, 값·URL 키는 식별자 그대로다. 결론 집계의 `'all'`은 "모든 모델 합계" 그대로다.
- 표시 이름에 버전을 넣지 않는다. 사전에 없는 새 식별자는 원문을 흐린 고정폭 글자 + "미등록 값" 툴팁으로 보인다(zeek_AD가 표에 행을 더한다).
- 툴팁 설명 속 "연결 수"·"연결" 같은 말은 zeek_AD 확정 문구 원문이라 화면 용어 재정비(세션)와 별개로 그대로 둔다.

## 수집 구간(캡처) 표시 이름 (T20, 출처 zeek_AD)

zeek_AD `docs/data-contract-v2.md` "수집 구간(캡처) 표시 이름" 절과 `docs/dashboard-handoff-2026-11-21.md`(zeek_AD 커밋 `0117401`, `docs/design-discussion-log.md` Q65)에서 확정한 규칙이다. 표시 이름과 실습망 덧붙임은 계약 표와 글자 그대로다. 툴팁은 계약의 '툴팁'·'내용' 칸을 아래 규칙으로 옮긴 글이다(`frontend/src/utils/labels.ts`의 `captureInfo`, 화면 요소 `CaptureName`). DB의 `capture_id`는 바뀌지 않는다. 이름은 zeek_AD가 2026-11-26에 바꾼 판이다(합성 APT → 합성 패턴, 실습망 시험 이름 측면 이동 → 공유 탐색, 느린 유출 → 분할 유출, T62).

| 캡처 ID 형식 | 표시 이름 | 툴팁(탐지 저장소 문구) |
|---|---|---|
| `cic17-<요일>` | CIC-IDS2017 <요일>요일 | 공개 데이터셋 CIC-IDS2017의 원본 트래픽(평가용). 월요일 정상만 학습에 썼다. |
| `syn1-<요일>` | CIC <요일>요일 + 합성 패턴 | CIC <요일>요일 Zeek 로그 사본에 합성 패턴 5종(beacon, 느린 유출, DNS 터널, 측면 이동, 느린 정찰)을 하나씩 코드로 끼워 넣었다. 네트워크로 보낸 트래픽이 아니다(탐지 저장소 설계 결정 DD-008). |
| `lab-YYYYMMDD` | 실습망 YYYY-MM-DD | 배포 VM이 격리 실습망에서 실제로 수집한 트래픽(날짜는 UTC). 하루가 처리 단위다. |

- 요일: `mon`·`tue`·`wed`·`thu`·`fri` → 월·화·수·목·금.
- 합성 패턴 5종의 종류 이름(beacon, 느린 유출, 측면 이동 등)은 찾으려는 행동의 이름이라 실습망 시험 이름과 달리 바뀌지 않았다(계약 그대로).
- 실습망 덧붙임(표시 이름 뒤에 " · "로 붙인다. 툴팁에 계약 '내용' 칸을 옮긴 글): `lab-20261119` "Kali 공격 + 정상 배경", `lab-20261118` "시험", `lab-20261201` "시험(가짜 패킷)", `lab-20261122` "Kali 공격 6종 + 타깃 VM", `lab-20261123` "시험(위 캡처의 뒤 시간)"(T39, zeek_AD `data-contract-v2.md` "실습망 캡처별 표시" 2026-11-23, `lab-20261122`는 T62에서 2026-11-26 판으로), `lab-20261124`·`lab-20261125` "유휴(규칙 전)", `lab-20261126` "오탐 규칙 뒤 재실행"(T66, 같은 표의 2026-11-26 갱신). `lab-20261122`의 툴팁은 공격 여섯(느린 스캔, 비커닝, 분할 유출, SMB 공유 탐색, SSH 무차별 대입, DNS 터널)과 "빠른 스캔은 lab-20261119에 있다"를 담는다. 표에 없는 새 `lab-*`는 덧붙임 없이 "실습망 YYYY-MM-DD"(zeek_AD가 표에 행을 더한다).
- 계약 글을 툴팁으로 옮기는 규칙(T62): ① 호스트 주소는 옮기지 않는다(화면 번들은 조회자 마스킹을 거치지 않는다). 그 자리는 "주소는 탐지 저장소 데이터 계약 v2 …"로 가리킨다 ② 마크다운 링크는 글자만 남긴다 ③ 백틱과 굵은 글씨 표기는 뺀다 ④ 문장 끝에 마침표를 붙인다 ⑤ 탐지 저장소 문서를 가리키는 출처 앞머리는 "탐지 저장소"다(예: "탐지 저장소 설계 결정 DD-008", "탐지 저장소 2026-11-19 전달 글 5절").
- 툴팁 마지막 줄에 원래 캡처 ID("캡처 ID: cic17-wed")를 둔다. 규칙에 맞지 않는 ID는 원래 ID를 흐린 고정폭 글자 + "미등록 값" 툴팁으로 보인다(`data-raw`).
- 열람 허용 패턴(`cic17-*` 등, 사이드바 "열람 허용 캡처"·사용자 관리)과 감사 로그의 대상 캡처는 ID 그대로 둔다.
- 좁은 칸(인시던트 목록 수집원 칸, 현황판 최근 인시던트·수집원 상태, 운영 현황 수집원 상태 표)은 **짧은 수집원 이름**(T24)을 쓴다: "CIC 수", "CIC+합성 수"(T62, 전에는 "CIC+APT 수"), "실습 MM-DD", 규칙 밖은 캡처 ID. 그 사용자의 허용 캡처 안에서 짧은 이름이 겹치면 연도를 붙인다("실습 2026-11-19"). 위 표의 전체 이름과 캡처 ID는 툴팁·화면 판독기 글자에 둔다.
- `lab-20261201`(VM 전에 만든 가짜 패킷)은 공개 데모 `demo` 계정에서 숨긴다(허용 캡처 `cic17-*,syn1-*,lab-20261119`, 2026-11-21 결정. T39부터 `cic17-*,syn1-*,lab-20261119,lab-20261122`이고 `lab-20261123`도 숨긴다. T66부터 `cic17-*,syn1-*,lab-20261119,lab-20261122,lab-20261126`이고 `lab-20261124`·`lab-20261125`도 숨긴다, 2026-11-26 결정). DB에서는 지우지 않는다.

## 운영 지표 정의 (T20, zeek_AD와 공유)

계산식은 zeek_AD `dashboard.feedback_summary` 뷰 정의(2026-11-21 `pg_get_viewdef`로 확인)를 따른다. 대시보드는 새로 계산하지 않고 뷰 값을 쓰며, 여러 캡처를 더할 때만 건수로 다시 나눈다.

| 정탐률 | 정탐 / 판정 완료 | `zeekad_precision` |
| 경보 정탐률 | 경보 발송 ∧ 정탐 / 경보 발송 ∧ 판정 완료 | `zeekad_alert_precision` |
| 경보 판정률 | 경보 발송 ∧ 판정 완료 / 경보 발송 | `zeekad_alert_resolved_rate` |
| 판정률 | 판정 완료 / 인시던트 | (계산) |

- **표본 부족**: 정탐률은 판정 완료가 10건 미만이면, 경보 정탐률은 경보 발송 ∧ 판정 완료가 10건 미만이면 숫자 대신 "표본 부족"을 쓰고 실제 값은 툴팁에 둔다.
- **문장 형식**(화면 `utils/operations.ts`와 API `FeedbackSummaryRecord#getPrecisionSummaryText`·`getAlertPrecisionSummaryText`가 같다. 두 시험이 같은 기대값 파일 `frontend/src/test/fixtures/feedback-summary-text-cases.json`을 읽는다): 모델 쪽은 "정탐률 60.0% · 분석가 판정 12건 / 모델이 올린 인시던트 18건", "표본 부족 · 분석가 판정 5건 / 모델이 올린 인시던트 2,277건", "분석가 판정 없음 / 모델이 올린 인시던트 5건", "분석가 판정 없음"(인시던트도 0). 판정이 있고 인시던트가 0이면 " / …" 없이 앞머리만("표본 부족 · 분석가 판정 3건"). 경보 쪽은 "경보 정탐률 75.0% · 분석가 판정 12건 / 경보 16건", "표본 부족 · 분석가 판정 4건 / 경보 6건", "분석가 판정 없음 / 경보 2건", "경보 3건 · 분석가 판정 수 알 수 없음", "경보 없음". 비율은 정탐률·경보 정탐률 하나뿐이고 소수 첫째 자리 퍼센트(반올림 HALF_UP), 건수는 천 단위 구분. **판정률·경보 판정률(판정 수 ÷ 인시던트·경보 수)은 화면·API 글에 쓰지 않는다**(`T67`. "판정 5/2,277건(0.2%)"이 모델이 5건만 잡았다는 뜻으로 읽혔다). 경보 판정률 열은 경보 판정 수를 되돌릴 때만 쓴다.
- **미탐(재현율)**은 탐지된 인시던트만 세는 이 집계로 알 수 없다.
- **합계 기준(현황판·운영 현황 상태 카드)**: 캡처별 "모든 모델 합계"(`'all'`) 행을 더한다(인시던트 목록과 같은 기준). 한 캡처에 `'all'` 행이 둘 이상이면 그 캡처의 최근 성공 탐지 작업과 같은 모델 버전 행 하나만 쓴다. 여러 캡처를 더한 정탐률은 정탐 합 / 판정 완료 합, 경보 정탐률의 분자는 행마다 경보 정탐률 × 경보 판정 수를 반올림해 되돌린 값의 합이다(경보 판정 1,000건 이상인 행이 있으면 계산하지 않는다).
- **탐지 모델별 행**은 주 탐지 모델(`zeekad_picked_by`) 기준이다. 교차 탐지를 빼지 않으므로 "단독 탐지"가 아니라 "주 탐지 기준 인시던트 수"로 쓴다.
- **탐지 작업 범위**: "데이터 기준"은 받은 탐지 작업 목록(열람 허용 캡처의 전체 기록) 중 가장 최근 성공 작업의 완료 시각, "실패한 탐지 작업"은 그 목록 전체의 실패 건수, 파이프라인 패널은 캡처마다 최근 작업 하나다.
