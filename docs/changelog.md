| `T60` | 2026-11-26 | 관리자 TOTP 확인의 실패 제한. 틀린 코드를 비밀번호 실패와 같은 횟수에 더하고 감사 `TOTP_FAILURE`로 남김. 한도(기본 5회)에서 계정을 15분 잠그고 그 세션을 끝냄(`423`). 서버는 코드를 보기 전에 조건부 `UPDATE` 한 문장으로 시도를 차지함. 그래서 동시에 온 요청도 한도보다 많이 판정받지 못하고 잠긴 계정은 다른 세션에서도 코드를 보지 않고 `423`. 비밀번호 실패 경로도 읽은 값으로 덮어쓰지 않고 같은 원자 증가를 씀. 관리자는 비밀번호가 맞아도 횟수가 되돌아가지 않고 TOTP 확인(처음이면 등록 완료)까지 성공해야 되돌아감. 화면은 `423`이면 로그인 화면으로 옮겨 서버 메시지를 보임. 공개 스택의 로그인 속도 제한에 `POST /api/auth/totp/verify`를 넣음. 앱 DB 표는 바꾸지 않음 |
| `T61` | 2026-11-26 | 공개 스택의 네트워크 분리와 컨테이너 권한(외부 검토의 지적). 일곱 서비스가 붙던 네트워크 하나를 둘로 나눔: `portfolio-net`(정의는 그대로)에는 `nginx-waf`와 앱만, 새 내부 전용 네트워크 `portfolio-data`(`PORTFOLIO_DATA_SUBNET`, 기본 `10.203.47.0/24`)에는 앱·DB·근거 API·초기화와 시드 도구. 그래서 인터넷 요청을 받는 WAF가 DB와 근거 API에 닿지 않음. 공개 스택의 모든 서비스와 VMware 구성의 두 서비스에서 capability를 빼고(`cap_drop: [ALL]`) 권한 상승을 막음. `postgres`는 root로 시작하지 않음(`user: postgres`). WAF 상태 확인 세 곳(두 compose, WAF 이미지)이 이름 `Host`를 보내 10초마다 남던 감사 줄을 없앰(WAF 규칙은 그대로). 리허설 `[T61a]`~`[T61e]`를 더하고 `api` 컨테이너에서 WAF로 보내던 `[T32c]`·`[T36b]`를 `portfolio-net`에 붙인 일회용 컨테이너로 옮김. E2E `[T61d]`·`[T61e]`(실행은 `T57`). NAS에 처음 반영할 때의 순서(`down` 없이)와 되돌리기를 배포 안내서에 적고, 배포 안내서에서 운영 기기의 모델·판·경로·여유 자원 수치를 뺌. 앞 작업 검토가 남긴 문장 손질(감사 줄의 `hostname`, 오류 로그의 차단 줄, 초기화 함수 셋, 공개 계정 비밀번호 서술) |

## 검증 단계 이름

`scripts/portfolio-verify.ps1`과 공개 주소 확인 출력의 `[T23a]`, `[T25c]`, `[T29e]` 같은 이름은 그 작업에서 더한 확인 단계입니다. 앞의 번호가 작업 번호이고 뒤의 글자는 같은 작업 안의 순서입니다. `[0]`~`[9]`는 `T10`·`T12`부터 있던 기본 단계입니다.
